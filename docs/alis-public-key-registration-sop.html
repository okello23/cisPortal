Standard Operating Procedure

A-LIS Remote Backup Keys

Procedure for registering an A-LIS facility SSH public key in the CIS Portal for remote backup access management.

1. Purpose

This SOP guides authorized CIS Portal users on how to register a facility A-LIS SSH public key in the CIS Portal so it can be deployed to the central backup server without manually editing the server-side authorized_keys file.

2. Scope And Roles

Use This SOP When

  • A facility is registering its first backup public key.
  • A facility server has been rebuilt and the SSH key changed.
  • An existing key must be updated in the CIS Portal.

Authorized Roles

  • ICT Support Staff
  • ICT Supervisor
  • ICT Manager
  • ICT Administrator

3. Prerequisites

  1. The facility A-LIS server has already generated its SSH public key.
  2. The public key has been copied from the facility server.
  3. The user has valid CIS Portal login credentials.
  4. The facility already exists in the CIS Portal facility list.
Expected key format 
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA... alis-offsite-backup

4. Procedure: Register The Public Key In The CIS Portal

1

Log Into The CIS Portal

  1. Open the CIS Portal in your browser.
  2. Enter your username or email address.
  3. Enter your password.
  4. Click Staff Login.

Screenshot Placeholder: Login Screen

Figure 1. CIS Portal login page

2

Open The A-LIS Remote Backup Keys Module

  1. From the staff dashboard, click Infrastructure in the top navigation.
  2. Select A-LIS Remote Backup Keys.

You should now see the A-LIS key registry page with the registered keys table, deployment controls, and audit history.

Screenshot Placeholder: A-LIS Remote Backup Keys Main Page

Figure 2. A-LIS Remote Backup Keys registry page

3

Start A New Key Registration

  1. Click the Add Key button.
  2. Wait for the key registration modal to open.

The modal includes the facility selector and the SSH public key input area.

Screenshot Placeholder: Add Key Modal

Figure 3. Add Key modal for registering a facility public key

4

Select The Facility

  1. Click the searchable Facility dropdown.
  2. Search using any of the following:
    • facility name
    • district
    • region
    • facility code
  3. Select the correct facility from the results list.
5

Paste The SSH Public Key

  1. Paste the copied public key into the SSH Public Key field.
  2. Confirm that the value:
    • starts with ssh-ed25519
    • is on one line only
    • does not contain private key content
ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAA... alis-offsite-backup
6

Save The Key

  1. Click Save Key.
  2. Wait for the system to validate and store the key.

If successful, the portal will generate a fingerprint, save the key, set deployment status to pending, and record the action in audit history.

Expected success message 
Key saved successfully. Pending deployment.

Screenshot Placeholder: Key Saved Successfully

Figure 4. Successful key registration and pending deployment status

7

Confirm The Registration

  1. Review the Current Key Status panel on the right.
  2. Confirm the correct facility is shown.
  3. Confirm the fingerprint is present.
  4. Confirm deployment status is pending.
  5. Review the registry table and audit history to confirm the action was recorded.

5. Updating An Existing Key

  1. Open the same key registration workflow using Add Key or Edit.
  2. Select the facility that already has a registered key.
  3. Paste the replacement public key.
  4. Select an Update Reason.
  5. If the reason is Other, provide a supporting comment.
  6. Click Save Key.

The system will preserve audit history and mark the updated key for deployment.

6. Expected Result

  • The facility public key is stored in the CIS Portal.
  • The fingerprint is generated and saved.
  • The key appears in the A-LIS registry table.
  • Deployment status is set to pending.
  • The action is captured in audit history.

7. Troubleshooting

Key Rejected

  • Confirm the key starts with ssh-ed25519.
  • Make sure the key is on one line only.
  • Make sure it is a public key, not a private key.
  • Check that the key is not already assigned to another facility.

Facility Not Found

  • Verify the facility exists in the CIS Portal facility list.
  • Search by district, region, or facility code.

Update Reason Required

This is expected when changing a facility that already has a registered active key.

Status Still Pending

The key was saved correctly, but it still needs to be deployed using Deploy Keys.
